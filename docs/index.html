llm_judge_audit — results

How reliable are LLM judges?

A statistical audit of LLM-as-judge reliability on MT-Bench: classical inter-rater agreement, a paired causal experiment on prompt design, and a hierarchical Bayesian model of judge ability and item difficulty.

Real data. 150 MT-Bench Human Judgments battles, judged live via the Anthropic API — 600 calls total on claude-haiku-4-5-20251001 (direct + chain-of-thought, both answer orderings, seed 42). No simulated inputs. An earlier run surfaced a real bug (CoT responses silently truncated before reaching a verdict); it's fixed, and this run's 0% unparseable rate confirms it stayed fixed.

Causal effect of chain-of-thought prompting

Paired, item-blocked estimate (see causal_experiment.py): every battle is judged under both prompt variants, so the comparison controls for item difficulty. Point = observed accuracy delta; whiskers = 95% item-level bootstrap CI; McNemar's p-value tests the same paired difference.

Bayesian judge reliability

Posterior ability for each judge config from the hierarchical Rasch/IRT model — a rater's tendency to agree with human ground truth, pooled across items, with a 94% credible interval. Ability is zero-centered by construction: a config right of the line agrees with humans more than the average config here.

Where each judge gets confused

Confusion matrix per config: rows are the judge's verdict, columns the human-majority label. Diagonal = agreement. tie (inconsistent) means the verdict flipped between answer orderings — humans never produce that label, so that column is always empty; it's kept for an honest count of how often each judge contradicted itself.

Accuracy by item difficulty

Battles bucketed by human_agreement — how unanimous the human raters were on that battle. If a judge tracks difficulty the way humans do, its accuracy should rise toward the right. Marker area is proportional to the number of battles in that bucket — the leftmost buckets are thin (2 battles) and noisy by construction.
